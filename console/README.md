## 操作

1. 选择 `demo-01` → Start（Init）→ 等待 Ready；需要运行运动策略时再点“模拟使能”。E-stop 对应模拟 Relax，关闭力矩并返回 Limp。
2. W／S 前进／后退，A／D 左右转；方向键同义。连续输入每 100 ms 更新。鼠标按住方向按钮也可以操作。
3. Space 仅停止行走，**不是力矩急停**；Esc 释放控制。松键归零、窗口失焦／切换标签释放；切换机器人会先释放旧设备。
4. 1 坐下／站起、2 地面拾取、3 左脚踢球、4 右脚踢球、5 翻滚。名称对应上游动作入口，模拟器只演示反馈变化，不执行官方动作轨迹，也不能据此验收动作正确性。
5. 接管独占到浏览器会话；其他窗口被拒绝。连续速度命令最多约 250 ms 有效，租约 800 ms 到期。停止行走或释放控制不会取消已开始的有限动作，界面保留动作执行状态。

## 数据含义

`position/requested/submitted` 内部单位 rad，界面显示 °；电压 V，温度 °C，电流 mA。舵机寄存器方向和机械方向校验分别显示。Dynamixel Homing Offset 已包含在位置读数中，显示层不会重复施加。

历史快照中的位置是 `(present_position - 2048) × 2π/4096` 的寄存器换算估计，机械方向及零位仍待实机校验，故不能代表当前姿态。它们保留在关节数字和参数中，三维窗口明确显示参考站姿，不将未标定历史寄存器解释为实测姿态。历史全部 P=400，未被改写；模拟使能后显示 P=200，仅是模拟状态。快照中 Hardware Error 0x01 与历史电压原样保留。

图表的 `submitted` 指安全限幅后成功交给总线写入接口的数值，不表示舵机已经到达。经用户批准，已在本地 `Safety::apply` 应用观测补丁，2026-10-28 在 Docker 内通过 21 项 safety 测试并完成 ARM64 编译。真实遥测协议仍仅公开限幅前 targets，不能填进 submitted；带测试的历史差异见 `integration/001-applied-with-tests.patch`，当前实现状态与[实机测试计划](../docs/testing/控制台分阶段实机测试计划.md)分别维护。

## 2026-10-29：本地四元数角度与显示零位

Head / Body orientation 两栏的 RPY 以 degree 显示，采用右手系 `Rz(yaw) * Ry(pitch) * Rx(roll)`。这轮按用户确认仅转换四元数，不从加速度/角速度估算姿态。当前 `openchicken-sensors-t3-v1` 仍只提供原始六轴数据，并拒绝 `imu` / `head_imu` 四元数；因此实机当前显示“等待四元数”，不能将本轮 UI 测试误记为实机姿态已接通。

后续机器人端接入需另行演进遥测协议和主机校验。前端显示契约为 `state.imu`（机身）及 `state.head_imu`（头部），每项含 `valid: true`、`sample_time`、`frame`、`quat: [w,x,y,z]`；可显式声明 `quat_order: "wxyz"`，其他顺序不接受。`sample_time` 必须与状态采样时间同域，不能迟到超过 250ms。有效有限四元数归一化后转换，无效/过期/失联显示未知。

`frame: "sensor_to_world"` 可在对应状态栏显示未校准传感器姿态；它不会冒充 `body_to_world` 驱动 3D。原 `body_to_world` / `head_to_world` 路径保持原有语义。

两栏右上角分别有默认关闭的校准开关。打开显示流程：保持相应部位静止于参考姿态，等待有效、稳定的四元数，手动点击“设为显示零位”。采用 `inverse(q_reference) * q_current` 再转 RPY，避免直接减欧拉角的跨界问题。关闭恢复原始四元数角度；头/身互不影响。它仅为当前浏览器会话的显示零位，不是陀螺零偏、加速度尺度或安装轴向标定，不修改遥测、录制原始数据、3D 姿态或机器人配置，也不发送控制命令。刷新、切换机器人、来源/坐标系变化或新启动会话会清除零位；失联清除零位；定格/回放禁止采集新的零位。

回归：`node tests/attitude.mjs` 与 `node tests/orientation-display.mjs`。浏览器测试数据覆盖无四元数等待、独立头身 RPY、零位设置/关闭、过期/失联、新会话清除、中英文及窗口布局；实机尚需四元数数据源。

## 2026-11-01 新机 SSH 只读检查（用户名＋密码）

测试页现已接入真实 OpenSSH 执行入口。监控主机需要 `/usr/bin/ssh`、`/usr/bin/ssh-keyscan`，机器人需要 SSH 密码登录与 Python 3；不安装机器人服务，不传输安装包，不使用 sudo。

操作步骤：
1. 新机建档，填写实际 IP、SSH 用户及端口（默认 22），保存并选择该机器人。
2. 在“SSH 实际检查”点击“读取主机指纹”。在机器人本机或可信记录核对 Ed25519 指纹；本机可执行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`，匹配后勾选并确认信任。读取公钥本身不代表已验证身份。
3. 输入本次 SSH 密码，点击 N01 连接与系统检查。后台通过 SSH 执行固定采集命令，返回系统、内存、磁盘、网络、实际 hostname 等结果；可以将实测 hostname 回填档案。
4. 按需再次输入密码，执行 N02 接口权限、N04 音频枚举、N05 服务与 IPC 路径检查。每个任务独立连接，不维持 SSH 会话。
5. 查看结果中的失败项与缺失数据，导出 JSON；结合现场观察填写下方验收结论。采集完成不自动判定通过。

N02 只检查设备路径及权限元数据，不打开舵机总线；N04 只枚举设备，不录音或播放；N05 只查询服务状态、监听端口和 socket 文件，不启动服务或调用 IPC。N03 配置写入、音频功能测试、策略推理、使能与运动等其他项目仍是操作说明与人工记录，尚未接入执行。SSH 检查返回一次性快照，不驱动 3D、关节图或曲线；这些视图继续使用原只读监控数据。动态 ZMQ 接入与双端密钥配置仍未实现。

主机指纹与任务结果保存在注册表同级的 `commissioning/trust/` 和 `commissioning/jobs/`。任务包含目标、时间、固定采集脚本 SHA-256、结果及错误；使用私有目录和原子文件写入。密码仅用于本次认证，不进入档案、任务文件、命令参数或环境变量；浏览器提交后清空密码框。SSH 使用独立临时 known_hosts 严格匹配已确认公钥，连接参数变更后需重新确认。检查有超时及输出大小上限，同一机器人不并行执行；刷新或服务重启不会自动重跑。
