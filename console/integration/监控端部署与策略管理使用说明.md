# 监控端部署与策略管理使用说明

2026-11-03，测试前修订。本说明对应监控端实现；不表示已在 Radxa 上执行升级或动作验收。

## 入口与连接

中文 `/commissioning/`，英文 `/en/commissioning/`。选中已保存的机器人档案后，下方切换「新机测试」「程序部署」「策略与技能」「蓝牙手柄」「历史与验收」。顶部、URDF、机器人状态和关节曲线保留。

首次在顶部「连接设置 / Connection settings」确认 SSH 指纹、填写密码。SSH、早期遥测、Robot paths & accounts 只在此配置一次，所有管理栏目共享。普通账户和管理员账户分别在当前页面复用凭据；切换目标、修改连接信息或刷新页面清除，不落盘。查询不再弹出重复密码确认；安装更新使用对应管理员账户。

## 阶段卡片与诊断

New robot tests 按 N01–N10 切换。N01/N02/N04/N05/N06 点击「检查本阶段」执行本阶段只读采集，也可从对应卡片发起检查。主页面仅显示状态、关键结果和操作；原始 JSON、日志、旧命令参考集中在顶部「诊断记录」，可导出。

每个阶段保留最近结果，不因执行其它阶段而丢失；结果是带时间的快照，变更配置后重新检查。缺失服务、未运行、权限未知与功能未验收分别显示。音频初始化允许已部署的替代服务，不要求重复安装。

N05 的 configd 卡片提供「检查」和「安装并启动」。后者内部完成检查、安装/启动和回查，无需手动复制终端命令或重复勾选。它不会启用 padd 或运控。系统配置仍使用既有管理员 SSH 方式，不使用 sudo。

N03 期望表、N04 双 IMU/电源实机反馈、N06 策略查询按阶段展示。尚未接入的录放音、相机和隔离推理明确标注待接入，不能自动标为通过。N07–N09 可从阶段卡片打开运行监控，进入页面不自动接管或执行动作。

N03 的可选机械核对和备注直接在关节表保存，旧人工记录可在 History 查看；其它阶段的人工验收在对应卡片「记录验证结果」中完成；检查完成与实物验收分别保存。待 deploy 配合的入口、结果格式和集中联调顺序见 [配置台重构与deploy端协作清单](配置台重构与deploy端协作清单.md)。

## N03：14 关节参数差异与回读

入口：「新机测试 → N03 舵机与机械」。表格包含逻辑关节、期望 ID、期望方向、期望 Homing Offset、实测值及比较结果。方向是 Drive Mode bit 0（0 正向、1 反向），不是 URDF 轴符号；偏置单位为 count。初始参考为全部正向、膝关节 ID13/23 偏置 −512、其他 0，必须按当前机器装配记录确认，不能直接视为已校准。

1. 编辑本机期望值，点击「保存表格」。机械核对和备注可留空，不再另外填写三个验收卡片。仅更新备注不会改变期望参数版本或使读回差异失效。重复 ID 会被拒绝。此操作只写机器人档案，不改舵机或 URDF。各机器按稳定档案 ID 分别保存版本和修改记录。
2. 核对「机器人端现有审计脚本」路径。默认 `<机器人部署目录>/scripts/audit-servo-config.py`，同目录必须有 `test-dxl-communication.py`。这是已有源代码脚本路径，不是 `current/bin/robotctl`；部署包仅有二进制时需要另行准备已审阅脚本或填写它们实际所在路径。监控端不自动上传、替换或执行未知版本脚本。
3. 固定支撑、确认无力矩，并手动退出所有总线访问程序后，点击「一键检查 · 参数差异与回读」。核对简短确认信息后执行。使用共享管理员 root SSH 凭据，不使用 sudo；主机指纹必须已核对。
4. 后端先校验两份脚本摘要，再核对 robotd/padd/netpadd/openchicken-agent 服务状态及串口占用，最后调用原只读审计。状态未知、活动服务、占用或工具缺失均拒绝，不自动停服务。现有脚本还有 UART5 校验、独占串口锁及白名单 Read 指令；不发送寄存器 Write、力矩、运动或重启命令。
5. 读取仅覆盖固定 ID10–14、20–24、30–33，UART5 / 1 Mbps；不扫描出厂 ID 或其他波特率。表格允许记录其他期望 ID，但此工具读不到的 ID 显示缺失，不会自动改地址。
6. 实测按 ID 匹配，比较 ID 寄存器、方向和偏置；同时保留完整寄存器及原始审计结果。力矩非零或任意硬件错误会单独标记，不忽略电压报警。修改期望值或切换地址后，旧记录不能表示当前检查通过。
7. 每次检查自动保存结果、时间、目标地址、期望值版本和日志。History 提供「查看读数与差异」，可追溯各次结果，无需手工点记录。关节表的机械核对/备注也进入同一历史；参数变动后对应关节的机械核对恢复为未核对。读取失败保留错误，旧读数仍明确标为快照。参数一致不会自动签收 N03，也不代表机械零位、实际运动方向或写后验收通过。

此版没有寄存器写入功能。需要改实际参数时先审阅旧值/新值并选用专用工具；修改后再按此入口回读。监控台使用当前仓库已审阅的两份脚本摘要：

- `audit-servo-config.py`: `acedff4f5314f90aeadf186eb476fc2739be84e8ad58b306ebe08cb9c7205bef`
- `test-dxl-communication.py`: `7d15b2a05e5433ca44a564461a97ddde7a0cb5174eae641a8b9b6f8a45f65ac0`

## Configd 安装与启动（SSH）

「新机测试 → N05 → 配置服务（configd）」直接调用监控台自带的 SSH 操作，不依赖本机 deploy 仓库，也不要求重新编译部署包。机器人须已上传 configd 和 robotctl，且 BlueZ 已运行。

1. 在机器人档案填写普通 SSH 用户，并在连接设置中核对、保存主机指纹。
2. 「连接设置 → 机器人路径与账户」只需核对共享设置：机器人部署目录、管理员账户 root、configd socket `/run/configd/configd.sock`。无需填写本机 deploy 仓库路径。
3. 点击卡片「检查」只读取现状；点击「安装并启动」在内部先检查，再应用并回查。首次需要管理员凭据时输入一次，其后同页复用；不再要求重复勾选。
4. 后端通过 SSH 创建/更新 configd.service，启用并启动 configd；有配置变更且服务已运行时重启该服务。无需 sudo。
5. 卡片显示实际安装/运行状态。完整服务差异、日志、验证结果与备份位置在「诊断记录」。验证包括服务运行、socket 存在，以及使用档案普通用户执行原生手柄状态查询。


`--allow-user` 授予该普通用户原生配置修改权限，范围不只蓝牙配对。此入口不安装系统依赖、不安装或启动 padd，不修改 robotd、不使能或执行运动。查询成功不代表手柄已经连接，也不代表 padd 或动作通过验收。

检查后目标、设置、脚本或板端状态变化会阻止旧预览执行。连接中断或验证失败时保留证据与错误，不自动重试或回滚；重新检查实际状态后再决定。已有自定义服务覆盖配置需人工审阅。蓝牙查询发现 configd 未安装、未启动或 socket 不匹配时会提示返回此入口处理。

## 程序部署

1. 保存**监控后端所在电脑**的 deploy 仓库路径，如 `/home/cyz/openchicken/openchicken_deploy`。
2. 在「程序部署」中展开「机器人路径与账户」，核对并保存一次。策略、蓝牙管理共用这份配置，其他栏目不重复显示设置表单；默认值符合实际部署时无需修改。核对机器人部署目录及程序更新使用的管理员 SSH 用户；策略及蓝牙操作仍使用档案中的普通 SSH 用户。
3. 在 deploy 仓库终端完成构建打包。页面「刷新版本」调用仓库固定入口 `deploy/radxa/deploy.py list --json`，列出已有包，不编译或下载程序。
4. 「查询当前程序」调用 `status`；「部署所选版本」调用 `apply --build-id ...`；「恢复上一程序版本」调用 `rollback`。预览包含版本、SHA256 和包元数据。
5. 核对目标并输入对应账户密码，页面显示逐行日志和最终原生结果。服务检查、停止与切换均交给 deploy 脚本；监控端不复制其实现，不执行自动使能。

程序部署面向已有服务安装的机器。首次系统依赖、设备权限和服务安装仍按新机流程处理。当前脚本只接受其实际支持的 target 字段，不提供尚未支持的服务组合选择。网络中断或主机重启导致结果未知时，先查询实际状态，才能再执行修改。

程序结果与遥测结果分别展示。成功更新后，监控端最多观察 10 秒，要求来自档案中同一真实地址的更新后反馈；更新操作还要求新 boot_id。未订阅显示 not_connected，未恢复显示 timeout，不将模拟数据或旧帧当作恢复。程序查询/更新前清除旧遥测通过显示。原生结果、时间、目标、包信息与日志进入 `program_deployment`；程序回退与策略版本恢复分别记录。

## 策略与技能

1. 「查询原生策略」读取 `robotctl policy --file ... list --json`，显示实际槽位及磁盘技能定义，同时尝试查询原生手柄绑定。旧版 CLI 不支持绑定查询时明确显示 unavailable。
2. 选择 ONNX 和可选 JSON。导入 JSON 会预填名称、用途、类型和持续时间；修改表单后保存的有效 JSON 采用这些值。Duration 不设任意默认值，应来自模型配套说明。执行 command、退出 command 固定为 [0,0,0]，退出时长固定为 0；页面不再提供这三个输入，即使原始或编辑后的 JSON 非零，新导入的有效清单也统一归零。原始 JSON 另存 original_manifest.json 并记录哈希。没有 JSON 时由表单生成清单。持续策略类型使用原生 perpetual，不使用 continuous。
3. 导入创建本机版本草稿，独立保存模型、原始 JSON、服务器计算的哈希和参数；不触碰机器人。支持原生 microduck / XL330 / 50 Hz / 61 观测 / 14 动作，以及 `microduck_supertracking_embedded_v1` 的 history[1,10,48] + time_step int64[1,1] → action[1,14]（50 Hz）。tracking 使用训练导出的 embedded 配套 JSON，名称和技能时长仍由表单填写，张量声明原样归档。这里不做 ONNX 推理，也不将声明检查视为模型有效性证明。
4. 先在程序部署页查询实际程序版本。选择归档版本，执行「新增 / 替换技能」或「替换策略槽位」。操作前和上传后分别读取原生机器人状态，要求策略关闭且 bringup=Limp；页面不会代替操作员停止、松力或使能。
5. 上传采用独立版本目录，校验模型和清单 SHA256；不覆盖已经存在且内容不同的版本。之后调用固定 `robotctl` 命令，并再次查询实际结果。
6. `add/remove` 不带 `--json`，确保沿用原生重载行为。加载槽位使用 `load ... --json`。`chain=true`、自定义 `action_scale/gain_ratio` 等当前 CLI 不能完整表达的参数会拒绝；已有这类定义也不能被静默覆盖或移除。
7. 槽位替换要求清单显式声明 slot。walk/stand 必须为 perpetual；kick/roulade 必须为 episodic。普通技能仅接受 constant-command episodic。phase/posture_flag 支持替换 sitstand/ground_pick 专用槽位。此操作只换模型，时序仍由原生 policy set 和 robotd.toml 决定；上传 JSON 的 ramp_s/period_s/end_phase 仅归档，预览明确说明，不会改写运行时序。可选槽可单独停用（原生 none），walk 不可停用。
8. 「移除技能定义」保留模型、参数、绑定快照和操作记录。「恢复历史策略版本」重新应用归档的模型、参数与原来的槽位或技能定义；绑定保留为可审阅草稿，需要单独发布。「槽位恢复出厂默认」调用 `reset`，不是历史恢复。

结果分开显示：

| 字段 | 含义 |
| --- | --- |
| config_result | 查询确认配置是否落盘；不只看退出码 |
| load_result | 槽位实际路径、运行开关和错误是否确认新模型；仅存在技能名称不足以确认同版本加载 |
| motion_test | 当前版本的人工实物验收，默认 untested |

原生接口不能证明自定义技能的具体运行版本时显示 `unknown`。上传成功、CLI 请求成功均不会自动变成动作通过。`runtime_tuning`、观测/动作描述等元数据用于归档与预览，不会改写机器人运行参数。

## 绑定与运行页接入

当前已实现绑定草稿、冲突检查、发布条件及档案记录。自定义键盘限制为 Digit6–Digit0，浏览器 Xbox 额外组合键为 LB+RB、LB+X、LB+Y；原有五个动作、LB+B、模式选择及 Start/Select 行为保留。

发布绑定核对本次部署 ID、目标、路径设置、当前程序版本、最新查询中的模型绝对路径和参数；仅同名技能存在不能作为证据。人工验收提交必须携带当前 deployment_id，并记录实际程序版本。重新应用、替换和删除会使旧验收不再作为当前通过依据；历史 tests 保留。程序变更或查询发现实际模型改变时撤下失效绑定。原生直连手柄支持五个 LB 技能组合键的绑定写入及单键恢复默认，写入后读回确认。

运行页显示原生已加载的额外技能按钮，便于首次验收；发布后启用键盘和 Xbox 快捷键。动作仍通过既有 ZMQ → agent → robot.do 链路执行。运行页链接不自动接管或触发动作。控制通道未就绪时立即报错，不排队或重试。

## 蓝牙直连手柄

- padd 配置默认使用部署服务约定的 `<deploy_root>/config/robotd.toml`；自定义安装可单独修改。绑定查询先只读核对运行中 padd 的 MainPID、实际 --config 和 --socket；路径不符或进程未运行时明确拒绝。配对/状态/解除配对使用 configd，不依赖这个配置文件。
- 蓝牙操作调用原生 `robotctl --config-socket /run/configd/configd.sock pad status/pair/forget --json`；绑定使用 `--pad-config ... pad bindings/bind/reset`。
- 配对前打开 Xbox，长按 Sync 至快速闪烁；可留空 MAC 扫描配对，默认 30 秒。解除配对必须指定 MAC。
- 配对返回 `outcome=failed` 即为失败，即使进程退出码为 0。解除配对 `removed=false` 是原生幂等结果，不伪装为错误。
- 配对或解除后尝试刷新状态，分别显示设备、信任、连接与 padd 状态。失败显示未知，不显示“没有手柄”。
- 运行页有独立蓝牙状态卡，显示最近 SSH 查询时间，明确为非实时快照；不会后台使用保存密码重连 SSH。
- BlueZ、configd 授权、padd 部署路径、输入权限、`netpad.enabled=false` 等前置配置仍需按原生部署流程核对；此页不自动修改系统服务。

## 档案与测试

数据在 registry 所在目录的 `commissioning/management/`，默认属于忽略 Git 的 `console/config/`。模型、凭据、目标配置和执行日志不进入源码仓库。任务 JSON 保存原生查询前后结果；进程中断标记 unknown，不自动重试。档案使用稳定 profile_id，改名、改 IP 或归档删除不丢失历史。

新增测试：`tests/test_management.py`、`tests/browser-management.cjs`、`tests/managed-bindings.mjs`。使用临时档案、模拟 SSH/native CLI 和隔离模拟页面。实机升级/回退、策略加载、蓝牙配对和实物动作需要后续单独验收。

## 测试前检查修订

测试中的状态订阅和命令通道分别等待完成握手；状态数据到达不表示 CURVE 命令通道已经可发送。没有增加命令排队、自动重试或延长机器人运动超时。

旧档案没有 deployment 证据时不能直接发布为已验收版本，需要在查询程序后重新应用并记录本次验收。配置落盘与原生运行版本无法核对时继续显示 unknown。特殊槽位有效时序验证、实机升级/回退、蓝牙配对及物理动作尚未验收。

新版 agent 随 deploy 构建包发布。未设置 pad_config 的现有 agent 配置默认读取同目录 robotd.toml，无需修改私有 JSON；已有显式路径保持有效。原生绑定变更后，浏览器 Xbox 使用相同的新绑定，配置摘要变化会要求重新接管。
