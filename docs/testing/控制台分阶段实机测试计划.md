| 编号 | 操作 | 通过标准及证据 |
| --- | --- | --- |

| D05 | 审阅本轮将启动的进程、数据源、设备读写和允许的命令 | T1–T4 后端拒绝 init、enable、速度、动作及寄存器写入，不只是在 UI 隐藏按钮 |
| D06 | 检查 UART5、I²C4、ALSA 权限和唯一所有者 | 使用 `/dev/openchicken-dxl`、`/dev/i2c-openchicken` 和已确认 ALSA 卡；无重复打开总线的进程 |
| D07 | 在无硬件/隔离测试中验证启动、退出和异常路径 | 没有意外总线写入或自动使能；真实部署前留有调用/假 IO 证据 |

**只读模式是入口条件。** 当前 `robotd --no-policy` 只禁用策略，不保证不配置总线、写寄存器或控制力矩；`--fake` 数据也不能作为真实反馈。若现有运控入口不能满足只读要求，应先实现并审阅受限采集路径。它作为唯一总线所有者只执行已批准的 Ping/Read，并把真实数据交给 agent；进入运控模式前停止该独立读取者、明确交接所有权。

仅用原有只读诊断脚本可以验收硬件，不能据此签收控制台端到端链路。是否采用独立受限采集入口还是已审阅的 robotd 只读后端，在 D05 固定，测试中不能混用两个读取者。

T1 系统状态本身不依赖 ONNX Runtime；若某个程序因运行库缺失不能启动，就暂不启动该程序，不能为提前看 CPU/ALSA 状态而放宽模型或硬件检查。

按配置采样周期对照更新节奏并记录丢帧；不新增“数据年龄”展示项。失联、未知或画面定格通过已有状态与来源标签表达，采样时间和序号保留在协议及测试日志中。

## 6 T2 音频枚举与实际功能

音频底层操作沿用[标准配置与测试流程](标准配置与测试流程.md)中的扬声器和麦克风章节，不在本计划复制驱动安装或 mixer 配置。已确认的 MK1 是单个物理麦克风，左右 ADC 采样不等于两只麦克风。

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| A01 | 对照已确认的声卡、PCM 和音频初始化服务 | 控制台枚举结果与指定硬件一致；服务 active 不能代替实际出声/录音 |
| A02 | 操作员准备后，以已验证音量播放一段短测试音 | 实装扬声器可听见，无明显破音、掉音或播放报错；记录当前 mixer，不自动改到最大音量 |
| A03 | 经确认后录制短暂安静段和说话段，在主机回放 | 信号随声音变化，非全零、持续满幅或明显削波；原始文件及格式留档 |
| A04 | 分别检查两个采集通道及既有 MK1 路由 | 与已确认接线一致；不把通道数量误报为物理麦克风数量 |
| A05 | 通过隔离测试模拟设备不存在/被占用，随后恢复 | 状态能区分未枚举、忙和未知；恢复正常；不为制造故障热插内部模拟麦克风接线 |
| A06 | 观察没有点击测试动作时的 agent 行为 | 不自动试播或持续录音来判断“就位”，不占用后续媒体服务所需设备 |

“已枚举”证明驱动端点存在，“实际出声/采集通过”是单独测试结论。模拟麦克风或扬声器导线断开不一定导致 ALSA 设备消失，不能声称仅靠枚举就能实时检测物理接线。

如果控制台尚无播放/录音入口，可人工在板端执行测试、在主机回收证据，并把 UI 入口记为待实现；不能把人工操作签成“控制台远程音频测试通过”。语音命令和 AI 对话保持 TODO。

## 7 T3 电源与无力矩关节反馈

### 7.1 电压和外部供电

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| P01 | 唯一总线所有者读取舵机电压并上报 | UI 标为 DXL 母线电压，单位 V；不能从 SBC 温度、额定电压或历史值生成 |
| P02 | 同步保存各舵机电压、有效位与总览数值 | 明确总览取值/聚合规则，能解释舵机间差异；无有效样本时未知，不显示正常的 0V |
| P03 | 稳定供电时用合适仪表对照同一母线测点 | 按仪表精度、舵机分辨率和测点压降确定误差预算并记录；不预设未校准的绝对精度 |
| P04 | 对照 Pin31 / GPIO3_B4 输入与控制台外部电源状态 | 使用 `gpio@fe760000` offset 12，高电平对应已确认的 DXL 电源存在；保持输入模式 |
| P05 | 在 DXL 无力矩、SBC 有已确认独立稳定供电时，受控改变外部 DXL 供电 | 状态按已配置去抖更新；不反复抖动。若不能保证 SBC 供电，暂不进行物理切换，记录阻塞 |
| P06 | 模拟电压样本丢失、GPIO 读取失败、告警恢复 | 各信号独立标无效，不能相互推断；外部电源存在不等于正在充电或电池百分比 |

电压阈值沿用审阅后的本机硬件基准，首轮不人为制造欠压/过压。历史 hardware_error=0x01 不能隐去；重新审计当前状态并查清原因，不以清除报警作为测试步骤。

### 7.3 关节曲线与录制

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| C01 | 无力矩时被动移动关节，观察反馈曲线 | 与现场动作和原始采样一致，单位、时间顺序正确，无明显反向跳变 |
| C02 | 查看 requested / submitted 曲线 | 未发送命令时显示无有效样本，不用反馈复制出“命令曲线”；accepted 不等于 submitted |
| C03 | 在模拟/假 IO 环境测试限幅及写入失败 | 请求与实际提交可区分；失败帧 submitted 无效；这部分先记为逻辑验证，真机闭环留到 T6 |
| C04 | 断开遥测、丢帧、重启采集进程 | 丢失段不画成连续有效曲线；boot_id 变化后不拼接旧轨迹，不跨时钟重置产生大跳变 |
| C05 | 选择不同关节、切换时间窗、悬停和导出 CSV | ID、曲线列、数值和单位一致；导出可回查同一帧 |
| C06 | 开始录制、定格画面、返回实时、结束录制、回放 | 使用既有命名；定格只冻结显示，后台继续收数；回放明确标识且拒绝真实控制；不恢复旧操控权 |

跟随误差基于有效的 submitted 与反馈及其采样关系计算；不同采样时刻需按协议说明对齐，不能把不同机器时间戳直接相减或把请求目标冒充已写入目标。

## 10 T6 受控使能、命令曲线和急停

进入本阶段前确认：T0–T5 相关项通过，机械方向/零位/行程明确，当前硬件错误已解释和处理，支撑或固定措施就位，现场可独立处理异常。首轮真实控制前先在假 IO 下验证所有拒绝、租约和锁存分支，再安排受控物理验证。

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| K01 | 无租约、错误身份、重复序号、过期或越界命令 | 机器人端拒绝且无硬件动作；服务端校验不能由前端代替 |
| K02 | 在批准范围内进行单关节最小幅度动作 | 先确认 P/I/D、限位和速度设置；请求、submitted、反馈对应正确，成功写入与到位分开表示 |
| K03 | 同步记录三条位置曲线和跟随误差 | 指令响应、限幅和反馈一致，无复制反馈伪造命令线，无意外跳变 |
| K04 | 固定/支撑下验证 E-stop | 映射 robot.relax，直接请求全部 14 DXL 断矩并锁存；逐 ID 回读确认。无法确认的舵机必须显示未知/失败，不能全部标“已断矩” |
| K05 | 急停后重连、刷新、普通 init、重复使能请求 | 不自动解除锁存或恢复运动；解除锁存与再次 init 是明确分开的动作 |
| K06 | 受控测试 Start/init | 只发送 init；显示接受、执行、完成或失败，不自动附加 enable 或启动策略 |
| K07 | 受控失焦、松键、标签切换、关闭浏览器、断网、agent 停止 | 连续速度按机器人端已配置的过期/租约机制归零；实测响应并对照参数，不套用模拟器时限 |
| K08 | 两个操作者争用及切换选中机器人 | 只有当前合法租约生效，切换时释放旧控制，不广播命令或重放排队命令 |

E-stop 接受机器人可能倒下，物理测试时仍需安排固定/支撑；它是舵机断矩与锁存，不是切断所有硬件电源。Space 是停止行走，不是 E-stop。停止行走也不一定中断已触发的有限动作，其实际状态机语义必须分别验证。

PID P=200 按已经确认的目标核对，但上电后的 RAM 值必须重新读出；若需修改，只能通过已批准的初始化补丁或独立写入步骤，不混入 T3 只读测试。历史全体 2048 目标测试超时不视为已完成默认站姿验收。

## 11 T7 策略移动与最终组合测试

先完成站立和最低已批准速度，再逐项增加，不从模拟器的速度上限直接推导真机上限。速度、时长、地面、负载、供电及监控开关均写入记录。

| 编号 | 测试顺序 | 通过标准 |
| --- | --- | --- |
| W01 | 默认 init 姿态，再受控启用站立/行走策略且零速度 | 没有意外移动、持续发散或关节限位冲突；状态与实际动作一致 |
| W02 | 最低已批准前进速度，松键停止；重复后再后退 | 方向正确，停止可预测；每次检查姿态、错误、温度及曲线 |
| W03 | 左转、停止、右转、停止，再组合短路径 | 方向与键盘映射正确，无跨动作遗留速度或持续积压 |
| W04 | 运动中按已批准工况检查断网/失焦/急停恢复 | 沿用 K04–K07 的本地保护，不因主机失联继续执行过期速度 |
| W05 | 相同短动作比较无监控、遥测、录制及可选视频 | 实际运动、控制周期和总线错误无可归因退化；有退化先降监控负载并修复 |
| W06 | 按实际 capability 测试坐站，再单独评审拾取、踢球、翻滚 | 每项具备模型和运行条件；显示接受、执行、完成/失败/中断；重复请求不重复触发 |
| W07 | 回放本轮记录并核对操作日志与曲线 | 能追溯命令、写入、反馈和状态事件；回放不会向真机发命令 |

拾取、踢球、翻滚不作为首次基础移动通过的条件；未准备好的动作继续禁用，不能为了覆盖 UI 按钮一次全部执行。动作名存在于模拟器不代表板端实际 capability 已就绪。

## 12 结束与交付

每轮记录结束时的实际 Torque Enable、锁存状态、采集/运控进程、策略状态和供电状态。确保本轮不需要的控制入口关闭、原有必要配置恢复；SBC 关机不能替代 DXL 力矩或外部电源确认。按现场安排结束服务，不通过自动停止流程触发未经检查的休息姿态。

首个里程碑是“真实只读监控通过”：S/P/J/C/N 基础项可追溯，麦克风/扬声器枚举准确，实际听音与录音另有证据，策略未启动、舵机未意外使能。第二个里程碑才是“受控运动通过”：Runtime/策略/机身输入、急停锁存、租约、初始化和基础移动均有实机证据。

当前建议首轮仅安排 T0–T4；先完成缺失的真实 agent 和只读遥测链路，再部署对应版本。完成基础监控后再进入 Runtime、策略和移动阶段，避免把通信、可视化、机械与策略问题混在同一次试车中。
