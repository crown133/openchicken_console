# OpenChicken 新机标准部署与测试流程

版本 V1，2026-10-30。依据 openchicken1 从硬件配置、机械装配调整、监控接入、策略部署到开机自启动的实际记录整理。本文是新机执行顺序和签收范围；本轮只整理文档，不实施测试，不开发自动化或控制台入口。

适用基线：Radxa ZERO 3W、Z3W-A1 HAT、14 台 XL330-M288-T、I²C 机身 LSM6DSV16X、头部 BMI088、AIC3104 音频。其他板型、器件或机械装配需要核对对应差异。样机通过的项目不能直接签为新机通过。

## 1 执行原则

- 本体硬件、Runtime 和真实观测推理在 Radxa 执行；主机负责构建、监控台、sim2sim 和结果归档。
- 正式运行时：robotd/DynamixelIo 管理 14 DXL 与机身 IMU，tofd 管理头部 IMU；监控端只通过现有 IPC 转发状态、命令和模式切换。不同 I²C 地址的正常共享不算冲突，同一设备不能被测试工具与运行时重复配置、采集。
- 首次硬件配置时，相关运行服务尚未启动或已停止，可使用专门的底层配置工具；进入正式运行阶段后，读取已有运控反馈，不再另起监控采集进程访问串口或 IMU。运控不涉及的音频、系统信息和 Pin31 沿用相应现有入口。
- 新机只做一轮必要配置读取和写后回读；不在每个子项前后重复全寄存器审计。已通过且没有相关改动的项目不重复。
- 原 MicroDuck Safety、deadman、范围限制和状态机保持不变；不新增监控端锁存、跨机时钟准入、额外 IMU 静置初始化/失效重置或固定长测门槛。
- 状态分别记录“通过、失败、待测、暂缓、不适用、现场确认接受”。配置回读、模型加载、物理动作分别签收，不互相替代。
- 原始配置、写入差异、版本与必要结论留档即可；不要求板端高频长期落盘、模型记录回放或故障矩阵。密钥只保存在对应机器的受限配置中，不进入普通测试报告。

## 2 标准顺序

| 阶段 | 做什么 | 完成依据 |
| --- | --- | --- |
| N01 建档与系统 | 确认硬件版本、供电、镜像、启动介质、网络和 SSH 身份 | 能稳定启动、登录，身份及镜像版本明确 |
| N02 接口与驱动 | 设备树、稳定设备别名、权限、Codec 驱动及音频初始化 | 重启后接口和权限存在，驱动与当前内核匹配 |
| N03 舵机配置与机械标定 | ID、波特率、模式、PD/PID、PWM Slope、偏置、方向和零位 | 参数写后回读、物理关节与映射一致 |
| N04 外设功能 | 扬声器、麦克风、两路 IMU、输入电压、Pin31 | 实际功能和显示相符；各项目独立签收 |
| N05 正式运控与监控 | 上线 robotd/tofd/agent，接真实反馈和 3D | 未使能，14 关节及两路 IMU 正常，约 50 Hz 运控 |
| N06 Runtime 与策略 | 固定模型版本、板端加载、观测顺序和推理检查 | 模型可加载、输入输出符合模型接口、观测来源正确 |
| N07 首次回位与松力 | 小幅动作确认，Start → Ready → 顶部急停/relax | 实际动作、反馈和状态转换一致 |
| N08 基础策略闭环 | Start → 策略使能，起身/站立、停止行走、松力 | 零速度下行为正常，停止语义明确 |
| N09 移动与动作 | 前进、后退、左转、右转，再逐项坐立、左右踢球、翻滚 | 每个方向和动作有实际结果，未测的不标通过 |
| N10 固化与开机验收 | 保存程序/模型/配置，安装服务，重启并自动重连 | 无需 SSH 启动，仍未使能，监控数据恢复 |

N03 与 N04 可按装配顺序交替推进，但各工具不能与现有硬件所有者争用。基础硬件确认后再进入 N05–N08。音频与嘴部等非行走项目可单独暂缓，不阻塞已经满足条件的行走链路；交付表必须保留暂缓项。

## 3 N01–N02：建档、系统和接口

每台记录 robot_id、hostname、普通用户、SSH 地址、主板/HAT 编号、启动介质、系统/内核版本、供电接法、舵机型号与固件、传感器安装照片。通用镜像和软件可复用，machine-id、SSH/CURVE 身份、网络地址、根分区标识和单机校准不能整份照搬。

本机已验证组合为 Armbian 26.8.1 / Debian 13 Trixie / 6.1.115-vendor-rk35xx。复用匹配内核的 Codec 驱动；不跨内核复制 `.ko`，不为部署顺带升级内核。

| 接口 | 本机基准 | 检查内容 |
| --- | --- | --- |
| DXL UART5 | OF `serial@fe690000`，Pin32/33；`/dev/openchicken-dxl` | 指向正确控制器，dialout 权限，没有串口控制台或其他进程争用 |
| 主 I²C4 | OF `i2c@fe5d0000`，Pin27/28；`/dev/i2c-openchicken`，100 kHz | 通过控制器身份建立别名，i2c 权限；不固定猜测 Linux 编号 |
| 音频 | I²S3 + TLV320AIC3104，Codec 0x18，卡名 `aic3104` | 匹配驱动、独立 12 MHz 晶振及实际板上时钟方案、playback/capture 端点 |
| 头部 BMI088 | 加速度 0x19、陀螺 0x68 | 芯片 ID 分别 0x1E、0x0F |
| 机身 LSM6DSV16X | J5、0x6A（新机按实际地址脚核对） | WHO_AM_I=0x70，接线和安装方向 |
| 外部电源检测 | Pin31，`gpio@fe760000` offset 12 | 保持输入和原 bias；高表示 DXL 外部电源存在 |

核对 overlay、别名及组权限后做一次重启复查。系统配置先看差异，再应用指定项目；不直接运行会同时启用升级、手柄、蓝牙等服务的整套上游安装器。

底层接线、音频和环境配置细节见[原硬件操作流程](标准配置与测试流程.md)及[环境配置说明](../../openchicken_deploy/docs/openchicken/README.md)。原硬件流程中的旧“尚未部署”结论属于历史阶段，当前部署进度以本文和具体验收记录为准。

## 4 N03：舵机通信、参数与机械零位

### 4.1 ID 分配和初次通信

| 右侧 ID | 关节 | 左侧 ID | 关节 |
| --- | --- | --- | --- |
| 10 | 右髋偏航 | 20 | 左髋偏航 |
| 11 | 右髋侧摆 | 21 | 左髋侧摆 |
| 12 | 右髋俯仰 | 22 | 左髋俯仰 |
| 13 | 右膝 | 23 | 左膝 |
| 14 | 右踝 | 24 | 左踝 |

头颈：30 颈俯仰、31 头俯仰、32 头偏航、33 头侧倾。共 14 个 DXL；不访问嘴部 DXL34 或旧版 IMU ID200。嘴部 PWM 另列选配。

新舵机先按实际出厂 ID/波特率识别，多个同 ID 舵机逐个配置，避免同地址冲突；不要全总线广播改成同一个 ID。最终使用 1 Mbps、Protocol 2.0、8N1。记录每个舵机的型号、固件、ID 与物理安装位置。本机历史实测型号 1200、固件 53；不能将它替代新机读取。

### 4.2 参数基准和分类

以下是当前项目的基准，不是所有项目都要重复写入，也不是所有工作阶段都固定为同一个增益。

| 参数 | 地址 | 本项目基准 | 配置原则 |
| --- | --- | --- | --- |
| ID | 7 | 按上表 | 单台配置，避免地址冲突 |
| Baud Rate | 8 | 3，即 1 Mbps | EEPROM；写后用新速率确认 |
| Return Delay | 9 | 0 | EEPROM |
| Drive Mode | 10 | 当前样机 0 | 方向/Profile 模式应匹配机械和运行时，不因左右镜像盲目翻转 |
| Operating Mode | 11 | 3，位置模式 | 与当前位置目标控制一致 |
| Protocol | 13 | 2 | 核对实际协议 |
| Homing Offset | 20 | 本装配基准：13/23 为 −512，其余 0 | EEPROM；机械基准匹配后使用，不复制未知装配的偏置 |
| PWM Slope | 62 | 255 | EEPROM；不是 PWM Limit，也不是外接 PWM 舵机的脉宽 |
| Shutdown | 63 | 52 / 0x34 | 项目既有值；不等于消除电压报警或解决电气供电问题 |
| Position P/I/D | 84/82/80 | init 和默认运行基准 200/0/0 | RAM；由运控按阶段加载，不能靠掉电保存 |
| Startup Configuration | 60 | 当前样机 0 | 核对上电自动力矩/RAM 恢复设置；与开机不自动使能约定一致 |
| Profile Accel/Velocity | 108/112 | 当前正常基线 0/0 | 历史 2/10 只用于一次临时限速实验，不固化成生产默认 |

位置 P/I/D 指舵机内部位置控制寄存器。当前 `set_gain(kp)` 写 P，I/D 写 0，未另加一层监控端 PD。阶段性站立软化、limp 等增益由原运行时选择，不要求运行中永远 P=200；过去静态审计值也不能代表掉电后的 RAM 值。

还应一次性记录 PWM Limit、Current Limit、速度/位置/温度/电压上下限、Status Return Level、Bus Watchdog、Hardware Error Status、Torque Enable。它们分别影响不同功能，不把“实测值”全部变为新机强制写入项。旧样机 2S 供电与电压报警的临时放行不能成为新机自动忽略报警规则。

执行顺序为：读取 → 列出必要差异（ID、旧值、新值、EEPROM/RAM、原因）→ 获准后在无力矩状态修改 → 回读确认。正式 DynamixelIo 当前不会自动修正 EEPROM，也不会自动收养未知 ID；这些属于首次硬件配置，不能假定服务启动就已配置完成。

### 4.3 零位和方向

1. 按装配图、夹具或明确零位标记安装舵盘/连杆，记录机械参考位置。
2. 无力矩时轻微活动对应关节，确认 ID 与正方向；已有可靠逐关节装配标定记录时复用记录，不重复一轮同样手工动作。
3. 检查 Homing Offset、Drive Mode 和机械关系；不通过对调软件按键或盲目改偏置补偿装反。
4. 固定支撑后进行必要的小幅验证，再进入整机回位。

本驱动 `角度 rad = Present Position × 2π/4096 − π`，软件 0 rad 对应 count 2048；舵机内部已应用 Homing Offset，显示和命令换算不重复加减。**所有关节 0 rad、装配零位、默认站姿和默认坐姿是不同目标。**Start 根据原姿态分类可能回 home 或 seat，不能把“全体写 2048”当作默认站姿验收。

参数历史来源和逐台审计见[舵机参数记录](../../openchicken_deploy/docs/openchicken/舵机参数配置.md)；其中早期动作失败和旧代码路径属于历史说明，当前实现见 [DynamixelIo](../../openchicken_deploy/openchicken-control/src/bus.rs)。

## 5 N04：音频、IMU 与电源

### 5.1 扬声器与麦克风

| 项目 | 已使用的配置 | 新机实际验证 |
| --- | --- | --- |
| 扬声器 | PCM 两路原始值 102（ALSA 80%，−12.5 dB）；Line DAC 118（0 dB）；Line Playback 0 dB、on | 枚举后播放短测试音，现场确认实装输出有声、无明显破音/掉音；回读配置并在重启后检查保持情况 |
| MK1 麦克风 | 单个物理 MK1，经 Mic3R 同时送左右 ADC；PGA 原始值 40/40（+20 dB），AGC off | 录制一小段安静和说话，再回放；分别确认两通道非全零、非持续削波且随声音变化 |

可沿用已验证的 48 kHz、S16_LE、双声道格式。一个 MK1 分到左右 ADC 不等于两只麦克风；两路播放测试也不代表实际装了两个扬声器。保存原始与处理试听结果的区别，不用加增益后的副本证明原始幅度合格。

音频初始化服务只恢复 mixer，不常驻播放或录音。监控枚举不主动打开录音流。远场、全双工、回声消除、声功率等列为扩展验收，不塞进基础行走放行条件。

### 5.2 两路 IMU

统一机器人坐标：X 向前、Y 向左、Z 向上。分别记录芯片轴向与机身/头部轴向，先按安装方向定义变换，再用静态重力和少量手动变化确认。

| 项目 | 当前实现/基准 | 新机检查 |
| --- | --- | --- |
| 机身 LSM6DSV16X | 芯片 Y 向前、X 向右、Z 向上；基本向量变换为 `[sy, −sx, sz]`；使用芯片 SFLP 和原解码器 | 静态重力、角速度、四元数及 3D 方向一致，安装牢固 |
| 头部 BMI088 | sensor→head 为绕 Z 180°；向量为 `[−sx, −sy, sz]`，姿态也转换一次 | 原始和头部坐标值都能解释实际头部姿态；不把机身水平等同于头部水平 |
| 单机校准 | 当前机身后端含 openchicken1 的水平修正/零偏常数 | 新机独立记录实际修正；不能把样机测量值当通用常数 |

先识别芯片，再看几秒静态采样；重力模长约 1g、角速度接近静止值，无明显饱和或卡住。随后只做足够确认方向的轻微前倾/侧倾/转动，现场能直接确认方向时不强制重复整套标定动作。**重力可以约束倾斜，不能单独确定绕竖直轴的安装方向或绝对航向。**

当前机身校准仍写在 [body_i2c.rs](../../openchicken_deploy/openchicken-control/src/body_i2c.rs) 中，尚不是通用单机配置文件。这是后续自动化前要明确处理的配置边界；本轮不改代码，也不新增校准门控。仅安装朝向相同，不足以证明静态偏置应完全相同。

生产频率、量程、滤波以运行驱动为准，并在报告中分别记录传感器 ODR、采集频率和监控显示频率。早期测试临时使用的量程/ODR，不自动写成生产参数。BMI088 INT1 是已做过的硬件能力项；生产轮询未使用它时，可作为该板型首次验证项，不要求每轮策略部署重复测试中断。

### 5.3 输入电压与 Pin31

- 通过 DXL 反馈读取母线电压；当前 robotd 汇总有效舵机电压，控制台直接显示缓存。手持仪表做一次粗略对照，记录测点是电池端还是 DXL 母线，不把两者当成完全同一点。
- Pin31 只判断 DXL 外部电源是否存在。确认无/有外部电源两种状态与 0/1 对应，条件允许时完成一次切换；不能据此判断正在充电、电量或 SBC 唯一供电来源。
- 整机软件重启不能替代电源切换测试。反灌、硬件切电能力、定量阈值等是独立硬件项，不默认已通过。
- 电压不是当前 61 维策略输入的一个独立维度；原控制器已有电压适配，当前默认参考电压为 7.4 V。记录其设置，不额外改模型输入，也不把显示电压等同于新电池保护功能已验收。

## 6 N05：正式运控与监控接入

硬件配置结束后停止临时工具，再启动本机适配版 robotd、`tofd --imu-only` 和 runtime_agent。确认同一个串口只有 robotd 使用；监控台不另开 DXL/IMU 采集。

检查项目：

1. 机器人身份、真实数据来源及在线状态正确；启动为 `Limp / enabled=false`，加载模型不等于使能策略。
2. 14 个关节的位置、速度、电流、温度、错误状态可读取；嘴部无反馈槽不伪造为真实测量。
3. 机身姿态、头部姿态、加速度和角速度的单位/坐标正确；3D 按 joint name 映射，四元数顺序正确，不二次安装旋转。
4. CPU、内存、SOC 温度、音频枚举、电压和 Pin31 来源于机器人。
5. 运控目标 50 Hz/20 ms；监控页面约 50 ms 更新，状态订阅和慢速系统状态频率分别记录，不能用页面帧率判断控制周期。

基础正常运行观察即可，不恢复 T4 综合长测、故障矩阵或监控负载矩阵，不要求绝对零丢周期。若频率持续不足，再分析读取、推理、日志等耗时；本机现有内核已做到约 50 Hz，不能直接归因于未安装实时内核。

## 7 N06：Runtime、模型和真实观测

先固定软件、Runtime 和策略版本，再做板端加载。当前参考组合：MicroDuck v0.17.8 / 942e58e 的本机适配 API47、ONNX Runtime 1.28.0、策略 v8 提交 `665ae4eb20bfe13bca1ef4ea6d4bb6b4a096e448`。复用发布包时记录本地适配版本和文件哈希，不能只写上游 tag。

| 策略槽 | 当前文件 | 使用顺序 |
| --- | --- | --- |
| walk | `velstand.onnx` | 先部署、先验证 |
| sitstand | `alpha_sitstand.onnx` | 随基础坐立和起身验证 |
| kick_left / kick_right | `ball_kick_left.onnx` / `ball_kick_right.onnx` | 基础站立、移动后分别验证 |
| roulade | `roulade.onnx` | 最后单独验证 |
| stand / ground_pick | 当前禁用 | 没有该功能需求时不纳入基本验收 |

模型材料先固定来源、版本和 SHA256，再纳入发布。分别确认 Runtime 动态库可加载、实际模型可加载、接口是 `[1,61] → [1,14]`；用一次必要的板端推理检查确认，不把哈希正确等同于推理通过。

61 维观测结构：机身角速度 3 + 投影重力 3 + 关节相对默认位置 14 + 关节速度 14 + 上一策略输出 14 + 命令 13。核对关节顺序、rad/rad/s、机身而非头部 IMU、默认位置扣除以及虚拟嘴部排除。上一动作是前次网络原始输出，不是已执行目标或舵机回执。

新硬件接入时核对真实观测；需要隔离推理时保持输出不下发，复用已有运行时读取/观测构造，不与正在运行的 robotd 争用硬件。现有 `Limp / policy=held` 只证明采集和保持循环，不能冒充策略闭环测试。无需重复历史板端记录回放或固定 3000 帧长测。

保留原模型的动作尺度、关节低通、增益及坐立参数；现场异常先检查观测、坐标、装配和跟随，不直接放大速度或反转方向来掩盖问题。

## 8 N07–N09：真实动作按顺序验证

实际使能和动作由操作员确认支撑、行程及停止条件后从控制台触发。准备动作与实际执行分开，后台部署不附带动作。

| 顺序 | 操作 | 看什么 |
| --- | --- | --- |
| 1 | 必要的单关节小幅验证 | 指定物理关节、方向、反馈和行程一致；仅对未确认的新装配做 |
| 2 | Start | init 打开力矩并斜坡回位；姿态分类可能选择 home 或 seat |
| 3 | 等 Ready，再顶部急停/relax | 实际松力、enabled=false；收到 accepted 不等于已经完成动作 |
| 4 | 再 Start，Ready 后手动策略使能 | 从坐姿正常起身或进入默认策略，速度请求先为零 |
| 5 | 短暂观察零速度站立 | 姿态与跟随正常，无意外请求；读取→推理→写入循环约 50 Hz |
| 6 | 分别前进、后退、左转、右转，松键停止 | 请求、实际应用命令、目标/反馈和实际运动方向逐项对应 |
| 7 | 坐下/站起 | `sit_toggle` 的完整过程及结束状态正常 |
| 8 | 左踢球、右踢球、翻滚，逐项进行 | 每个动作单独判断，不用模型加载成功代签 |
| 9 | 顶部急停/relax 结束 | 明确最终运行状态和现场松力情况 |

当前按键是固定请求，不是增量：W/↑ 为 vx=+0.12 m/s，S/↓ 为 −0.12 m/s，A/← 为 vyaw=+0.4 rad/s，D/→ 为 −0.4 rad/s，vy=0。按住每 100 ms 发送，松键请求归零，原运行时 EMA 继续平滑；长按不逐步加速。左右均以机器人自身坐标解释。

“停止行走”/Space 调用 robot.stop，归零速度、保持策略；顶部急停调用 robot.relax，关闭力矩并清除使能。失联的原版 500 ms deadman 归零速度，不等于自动断矩。网页急停依赖通信，不把它描述成独立硬件急停。

控制台当前动作键：1 坐下/站起、3 左踢球、4 右踢球、5 翻滚。动作完成要看真实反馈和状态，不能只看按钮可点或 RPC 成功。

## 9 N10：固化、开机与交付

保存通用版本、单机配置和验收结果三部分：

- 通用版本：本机适配二进制、协议/监控代码、Runtime/依赖版本、模型固定提交和 SHA256。
- 单机配置：身份/设备路径、音频 mixer、IMU 朝向与校准、关节 ID/方向/偏置、EEPROM 差异、运控参数、运行阶段增益。密钥就地保存。
- 验收结果：阶段结果、实际版本、必要采样/截图、人工确认、遗留问题和备份位置。

运行布局复用已验证方案：`current → releases/<版本>`；`config/`、`policies/`、`deps/`、`state/`、`backups/` 分离。无需沿用 `console-tests` 临时路径。RAM 增益由运控初始化恢复；音频 mixer 由既有音频初始化服务恢复，不把磁盘备份误认为芯片 RAM 掉电保持。

安装 robotd、tofd 和 openchicken-agent 三个开机服务；沿用必要的音频初始化服务。上电启动进程、采集和监听，不自动 init、enable 或恢复上次运动请求。检查一次真正重启：服务自行启动、硬件所有权正确、监控自动重连、关节/IMU/电压恢复、仍未使能。重启后运动测试只有确有变更时才重复。

现有 [Radxa 服务文件](../../openchicken_deploy/deploy/radxa/) 和 Pin31 入口绑定 `openchicken1` 用户及路径。它们是已验证样机配置，不是可直接拷到任意新机的一键安装器；后续自动化设计时再统一参数化，不在本次顺带实现。
