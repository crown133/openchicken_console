# OpenChicken 标准配置与测试流程

> 2026-10-30 更新：从新机硬件配置到策略部署、动作验证和开机固化的当前完整顺序，见[新机标准部署与测试流程](新机标准部署与测试流程.md)。本页保留早期硬件操作细节；“尚未部署”等进度和临时测试门槛为当时记录，不覆盖新版流程。

版本 V1，整理日期 2026-10-27。适用于 Radxa ZERO 3W、OpenChicken Z3W-A1 HAT、TLV320AIC3104 音频、板载 BMI088、J5 LSM6DSV16XTR 和 14 台 XL330-M288-T。依据 2026-10-25 至 27 日的实板测试编制，覆盖环境配置、外设功能和舵机通信；机械校准、完整动作及整机运控尚未验收。

新机器人从[验收记录模板](新机器人验收记录模板.md)复制一份到本机 `robots/<机器人编号>/records/`，逐项填写。`openchicken1` 的[本次总结](../../robots/openchicken1/records/2026-10-25至27-硬件测试总结.md)只作为参考，不能作为另一台机器的通过证明。适用硬件、器件或内核发生变化时，先重新确认对应配置。

Web 控制台与真实机器人链路另按[控制台分阶段实机测试计划](控制台分阶段实机测试计划.md)执行；本页底层硬件通过不能替代控制台端到端验收。

## 1 文件与操作约定

- 通用开发源码为 [`openchicken_deploy/`](../../openchicken_deploy/README.md)，已部署的通用版本保存在 [`common/`](../../common/README.md)。机器人身份、机械校准和验收结果放在 `robots/<机器人编号>/`。
- 文档、记录和证据只在开发电脑归档；板端保存部署程序、配置及测试脚本。录音直接经 SSH 输出到本机。现有 J5 脚本需要结果目录，测试时使用板端 RAM 临时目录，取回校验后清理，不在 SD/eMMC 留档。
- 新机器人必须使用自己的主机名、用户、网络配置、根分区 UUID、machine-id 和校准数据。不得整份覆盖其他机器的 `armbianEnv.txt`、身份配置或系统状态。
- 下文命令是后续人工操作流程，本次文档整理不执行。板端命令从已部署工程根目录运行；系统安装或权限调整使用明确的 root 会话，不使用 `sudo`。播放、录音、传感器临时配置和舵机动作各自确认后执行。
- 机器人服务保持停止。系统配置先 `--plan`、审阅后 `--apply`，重启另行安排。舵机参数写入、重启、使能与运动不能混入自动外设验收。

## 2 建档与基础环境

记录主板/HAT 版本和编号、BOM 差异、IMU 安装方向照片、扬声器接口与阻抗功率、供电拓扑、舵机型号/固件及各关节实装 ID。左右以机器人自身为准。

已测试的软件组合是 Armbian 26.8.1 Minimal、Debian Trixie、`6.1.115-vendor-rk35xx`，上游 MicroDuck `daemon-v0.17.8`，提交 `942e58e3aa6dbb28e7037203fff11866122c7567`。这是复现基线；其他版本须重新验证驱动、DTB 和脚本，不能把现有 `.ko` 跨内核复制使用。

板端只读检查：

```sh
cat /etc/armbian-release
uname -r
findmnt -no SOURCE /
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
systemctl --failed --no-page
systemctl is-active robotd.service padd.service netpadd.service
export PATH="$PATH:/usr/sbin:/sbin"
command -v python3 dtc fdtget fdtoverlay amixer aplay arecord modinfo dkms gcc make gpioget i2ctransfer
id
```

未安装的机器人服务显示 inactive/unknown 并返回非零状态不等于系统故障；不得为了让检查返回成功而启动它们。确认实际启动介质；本次 SD 启动可继续测试，eMMC 修复不作为外设测试前置条件。

所需工具：Python 3、device-tree-compiler、alsa-utils、i2c-tools、gpiod、udev；Codec 模块缺失时还需 DKMS、gcc、make 和与运行内核完全匹配的 headers。安装前检查发行版包版本，避免顺带升级内核。核对：

```sh
cat "/lib/modules/$(uname -r)/build/include/config/kernel.release"
modinfo snd-soc-tlv320aic3x
modinfo snd-soc-tlv320aic3x-i2c
```

headers 的 release 必须等于 `uname -r`。`modinfo` 不存在与“模块不存在”是两类问题，先核对 PATH。

## 3 接口配置与普通用户权限

详细实现以[环境配置说明](../../openchicken_deploy/docs/openchicken/README.md)为准，针序以[硬件交接](../hardware/硬件测试开发交接文档.md)为准。

| 通道 | 固定硬件身份 | 本次实例与预期 |
|---|---|---|
| I²C4 | `i2c@fe5d0000`；J4 Pin27 SDA、Pin28 SCL | `/dev/i2c-openchicken` → `/dev/i2c-4`，100kHz；root:i2c，0660 |
| DXL UART5 | `serial@fe690000`；Pin32 TX、Pin33 RX | `/dev/openchicken-dxl` → `/dev/ttyS5`；root:dialout，0660 |
| I²S3 | Pin12 BCLK、35 LRCLK、38 SDI、40 SDO | ALSA 卡名 `aic3104`，不依赖 card1 编号 |
| BMI088 INT1 | Pin15，GPIO3_B0 | gpio@fe760000 的 offset 8，按实际映射核对 |
| 电源存在输入 | Pin31，GPIO3_B4 | gpio@fe760000 的 offset 12，实例 line 名 `PIN_31` |

先配置指定测试用户的 I²C 工具和组权限，以下用户名替换为本台实际用户：

```sh
ROBOT_USER='本台实际用户名'
sh scripts/setup-i2c.sh --plan "$ROBOT_USER"
```

审阅后在 root 会话运行 `sh scripts/setup-i2c.sh --apply <实际用户名>`。音频用户需属于 audio 组，串口用户需属于 dialout 组；缺少时由 root 使用 `usermod -aG` 追加实际用户，保留原有组。重新登录后检查 `id -nG`，不能只在旧 SSH 会话判断新组是否生效。

```sh
sh scripts/setup-board.sh --plan
sh scripts/setup-audio.sh --plan
```

在匹配内核及依赖确认后，如 Codec 模块缺失，由 root 单独执行 `sh scripts/setup-audio.sh --install-driver`。审阅音频预览后执行 `sh scripts/setup-audio.sh --apply`；它同时准备基础 HAT 配置，通常无需再重复应用基础入口。仅配置基础接口时才单独使用 `setup-board.sh --apply`。这些应用步骤不自动重启。

用户安排重启后：

```sh
python3 deploy/openchicken/configure_hat.py --verify
sh scripts/setup-audio.sh --verify
readlink -f /dev/i2c-openchicken
readlink -f /dev/openchicken-dxl
ls -l /dev/i2c-openchicken /dev/openchicken-dxl
id -nG
cat /boot/armbianEnv.txt
```

基础与音频 overlay 的顺序应为 `openchicken-z3w-a1 aic3104-i2c4`，保留本台原有 rootdev、console 和其他有效设置。J7 默认 none；PWM8/9 仅配置控制器，不输出 PWM。UART2 调试保留。

## 4 共用 I²C 总线规则

| 器件 | 7 位地址 | 识别或使用方式 |
|---|---:|---|
| TLV320AIC3104 | 0x18 | 内核 Codec 驱动占用，通过 ALSA 操作 |
| BMI088 加速度计 | 0x19 | 0x00 读取 0x1E |
| BMI088 陀螺仪 | 0x68 | 0x00 读取 0x0F |
| J5 LSM6DSV16XTR | 实测 0x6A，备选 0x6B | WHO_AM_I 0x0F 读取 0x70；由模块地址脚决定 |
| HAT EEPROM | 设计 0x50 | 本流程不进行写测，实装与业务功能待验收 |

地址来自器件和硬件地址脚，不能用修改 Linux 总线编号解决地址冲突。I²C4 总线速率统一为 100kHz；本流程不为每个器件设置不同总线速率。IMU 内部 ODR 可以各自不同，与 I²C 时钟、用户态轮询频率分别记录。音频数据经 I²S3，不占 I²C 传音频。

按已知地址定向读取，避免全总线盲扫，不使用强制占用参数访问内核已绑定的 Codec。新机修改上拉、电缆或接入器件后重新核对电气波形；400kHz 尚未验收。

## 5 扬声器配置与验收

链路为 I²S3 → TLV320AIC3104 → PAM8406 → 扬声器。核对独立 12MHz 有源晶振实装及功放供电。原样沿用配置的前提是该时钟方案一致；声卡出现和 aplay 返回成功都不能替代实际听音。

默认固化值：PCM 两路原始值 102（ALSA 80%，-12.5dB），Line DAC 两路 118（0dB），Line Playback 增益 0dB、开关 on。80% 是 mixer 标度，不是声压或功率的 80%。配置文件及服务见[音频机制说明](../../openchicken_deploy/docs/openchicken/README.md#扬声器配置)。

```sh
cat /proc/asound/cards
aplay -l
systemctl status openchicken-speaker-init.service --no-pager
amixer -c aic3104 cget name='PCM Playback Volume'
amixer -c aic3104 cget name='Line Playback Switch'
```

服务预期 enabled、active (exited)、成功退出；它配置播放和采集，不持续播放或录音。若需人工重新加载已审阅配置，由 root 重启该服务，随后回读 mixer。

操作员准备好后播放短测试音：

```sh
speaker-test -D plughw:aic3104 -c 2 -r 48000 -F S16_LE -t sine -f 440 -l 1
```

记录每个实际装配输出是否出声、明显噪声、失真、掉音及 ALSA 错误。双声道测试信号不代表硬件必然装了两个扬声器。首次无声先检查接口、功放电源和 mixer，不把最大音量作为所有新机的固定步骤。验收后回读默认 80%，重启后复查一次。本次已通过出声与试听，输出功率、频响和长时温升未测。

## 6 麦克风配置与验收

板载 MK1 为模拟麦克风，通过 Codec ADC 和 I²S3 采集。驱动把使用的输入显示为 `Mic3R`。当前将同一个 MK1 同时路由到左右 ADC，左右 PGA 都为 +20dB（原始值 40），AGC 关闭；两个声道不代表两只独立麦克风。

```sh
amixer -c aic3104 cget name='PGA Capture Volume'
amixer -c aic3104 cget name='PGA Capture Switch'
amixer -c aic3104 cget name='Left PGA Mixer Mic3R Switch'
amixer -c aic3104 cget name='Right PGA Mixer Mic3R Switch'
amixer -c aic3104 cget name='AGC Switch'
```

预期依次为 40,40；on,on；on；on；off,off。需要重设时，审阅后执行 `sh deploy/audio/aic3104-mic-init.sh`，它不开始录音。

录音开始前先确认操作员已准备好；安排 15 秒内正常说话、停顿、轻拍一次桌面。以下在**开发电脑**运行，预先把 `ROBOT_SSH` 设置为本台 SSH 目标，把 `RUN_DIR` 设置为本机 `artifacts/hardware-tests/` 下新建的唯一目录，确认文件名尚不存在：

```sh
ssh -T "$ROBOT_SSH" 'arecord -q -D plughw:aic3104 -f S16_LE -r 48000 -c 2 -d 15 -t wav' > "$RUN_DIR/mic.wav"
ssh -T "$ROBOT_SSH" 'aplay -q -D plughw:aic3104' < "$RUN_DIR/mic.wav"
```

第一条会录音，第二条会经机器人扬声器回放。录音不落板端磁盘。分别检查两路有效信号、静音段与说话段变化、削波和声音可辨识度；分析时排除起始 2 秒的 ADC 瞬态，同时保留原始文件不覆盖。若生成去直流或增益调整的试听副本，单独标明处理，不能据此宣称原始幅度已合格。

本次只在右 ADC 开启时完成了清晰回放验收；之后左右 +20dB 的配置回读已通过，双通道录音仍须补测。远场、定量信噪比、全双工与回声消除均单独列为待测，不由一次听音签收。结论在本机归档；录音是否保留按该次任务约定处理，不默认长期保留。

## 7 板载 BMI088 配置与验收

先确认当前 `/dev/i2c-openchicken` 对应的数字总线号。以下 4 是本次实例，只有核对确实为 I²C4 后才使用：

```sh
i2ctransfer -y 4 w1@0x19 0x00 r1
i2ctransfer -y 4 w1@0x68 0x00 r1
```

两组 ID 分别应为 0x1E、0x0F，定向读取三次一致。读取寄存器地址阶段有写入地址字节，但不写配置寄存器。

动态测试按以下次序实施，操作员准备好后再启动：

1. 记录原电源、量程、滤波、中断配置。确认没有其他采样者和运控占用。
2. 复现本次临时测试条件：加速度 ±6g、陀螺 ±2000°/s；加速度 ACC_PWR_CTRL(0x7D)=0x04、ACC_PWR_CONF(0x7C)=0x00，按数据手册等待稳定；陀螺 GYRO_BANDWIDTH(0x10)=0x07，100Hz 输出、32Hz 低通，回读可能包含只读 bit7。本流程不把这些测试值固化为运控参数。
3. 静置约 5 秒，记录三轴均值、标准差、加速度模长、温度、饱和和通信错误。静止重力模长应接近 1g；本次 0.98937g 是样机记录，不是每台必须复现的标定常数。批量定量容差尚待冻结。
4. 再静止、缓慢前后/左右倾斜并转动、恢复静止。检查对应加速度和角速度变化、有无饱和、卡住或丢样。用户态轮询目标 50Hz 与传感器 ODR 分别记录。
5. INT1 单独测试：确认 Pin15 / GPIO3_B0 为未被占用的输入，临时设置加速度 INT1_IO_CONF(0x53)=0x0A，并将 INT1_INT2_MAP_DATA(0x58) 的 bit2 置位，其他位保留。捕获边沿并记录频率；主控 GPIO 不得改为输出。
6. 正常退出、异常或中断后均恢复测试前配置并回读。断电或强制终止后必须重新核对，不假设 finally 已运行。

本次已完成静态、动态和 INT1 功能测试；细节在[环境记录](../../openchicken_deploy/docs/openchicken/README.md#板载-imu-测试)。**目前工程中没有归档成通用入口的 BMI088 动态/中断测试脚本**，上述为复现规范；新机执行前需补齐并审阅采样与恢复实现，不得把历史样机结论填为新机通过。专用脚本、批量容差、零偏、轴向变换、同步及融合列入后续完善项。

## 8 J5 机身 IMU 配置与验收

断电核对 J5：1 GND、2 +3.3V、3 SDA、4 SCL；器件为 LSM6DSV16XTR。J5 没有中断线，本轮用轮询。上电后普通用户在板端工程根目录执行：

```sh
python3 scripts/test-j5-imu.py
```

默认只识别 0x6A/0x6B 和配置，不启动采样。预期恰好一个地址 WHO_AM_I=0x70；两个都存在时先确认接线和目标，再明确 `--address`。

操作员准备好后，使用板端 RAM 临时目录，替换为本次唯一名称：

```sh
python3 scripts/test-j5-imu.py --seconds 20 --output /dev/shm/openchicken-j5-本次唯一编号
```

先静止几秒，再缓慢倾斜和旋转，最后静止。测试自动临时设定 ±2g、±500°/s、两组 ODR 120Hz、BDU/地址自增，目标轮询 50Hz；记录三轴、温度、饱和、错误和恢复状态。输出目录已存在会拒绝运行。

结束后在关机前把该唯一临时目录取回本机 `artifacts/hardware-tests/`，逐文件核对大小和 SHA256；将结论填写在 `robots/<编号>/records/`。仅在取回及校验成功后清理该次明确的板端 RAM 目录，不使用面向整个工程的通配删除。临时文件不进入板端持久存储，后续可把脚本完善为直接输出到本机。

验收需满足正确 ID、有效静态/动态响应、无原始值饱和或通信异常，且 `report.json` 的 `restored=true`。脚本退出或报告有错不得签通过。静置加速度接近 1g；本次 1.00542g 和陀螺偏置仅是样机参考，不直接复制为新机校准值。

`Permission denied`：重新登录并核对 i2c 组和节点权限。`Resource temporarily unavailable`：先查是否另一个测试持有锁，等待其正常结束；提权不能消除并发冲突。该锁只协调遵守锁的工具，不代表总线上不同地址不能共存。测试后复查音频，验证共享总线使用未破坏既有配置。

## 9 外部电源存在检测

电路为 DXL_PWR → R24 10kΩ → Pin31，D2 3.3V 齐纳钳位、C44 10nF。它表示 DXL 外部电源存在，不能测量电池电压，也不能据高电平判定 SBC 此刻完全由哪一路供电；USB-C 与外部电源可能同时存在。

按设备树 `gpio@fe760000` 找到实际 gpiochip，确认 GPIO3_B4 offset 12 / `PIN_31` 空闲且为输入。以下 `/dev/gpiochip3` 是本次已验证实例：

```sh
gpioinfo --chip /dev/gpiochip3
gpioget --as-is --numeric --chip /dev/gpiochip3 --by-name PIN_31
```

命令对应 libgpiod 2.x；先核对版本和映射。需要权限时使用 root 会话。保持输入和原 bias，不使用 gpioset。

由操作员安排供电状态，分别确认“仅 USB-C、无 DXL 外部电源”与“DXL 外部电源确实接入”，各读取 10 次，记录稳定性、实际电源接法和测量时间。当前板验证为无外部电源 0、有外部电源 1。先安排稳定的 SBC 供电，不在运动或写盘过程中任意切断供电。

实际 GPIO 电压、判定阈值、连续切换、SBC 断电后的反灌电未测，需硬件测量另行验收。普通 2S 电池的 **7.0V 扬声器预警、6.6V 强告警并受控回蹲后掉电、监测锁存及复位**仍为运控 TODO；不能把 Pin31 或舵机低压寄存器当作该功能已实现。实际切断负载的硬件能力也待确认。

## 10 舵机通信与参数验收

完整 ID、寄存器、增益与来源由[舵机参数配置文档](../../openchicken_deploy/docs/openchicken/舵机参数配置.md)维护。本流程规定执行顺序，不将样机机械标定当作通用数值。

### 10.1 通信与配置只读检查

J13/J14 并联在同一 TTL 总线，经 UART5；1Mbps、Dynamixel Protocol 2.0、8N1。14 个 ID 为 10–14、20–24、30–33；无嘴部 34、无原版 imu_to_dxl 200。50Hz 是原版运控循环频率，当前尚未部署，不能由串口波特率推断。

```sh
python3 scripts/test-dxl-communication.py
python3 scripts/audit-servo-config.py
```

逐个确认型号 1200、固件、ID 与关节标签；Ping/Read 应答完整、CRC 错误和超时为 0。确认全部 Torque Enable=0，并记录 Hardware Error Status、供电和温度。只读配置正确不等于物理 ID、方向和零位已确认。

原版参数基准：Baud=3、Protocol=2、Return Delay=0、PWM Slope=255、Shutdown=52；init PID=200/0/0，P/I/D 是 RAM 参数，断电后必须重新审计并在获准初始化时加载。Homing Offset 原版 ID13/23 都为 -512、其余 0，但须完成下节机械核对才可用于动作。

记录差异后形成“ID、地址、旧值、建议值、EEPROM/RAM、原因”的修改表。用户确认后，在扭矩关闭时逐项写入并回读，再做独立审计；现有一次性参数修改程序绑定 `openchicken1` 的既有状态，不直接当作新机批量初始化器。

Shutdown=52 不清除已经存在的电压报警，也不自动解除先前停机锁存。本台用户明确同意的 2S 电压报警放行仅是该次测试约定；新机器需独立核对电源和批准条件。现有站姿脚本含该特例，使用前必须审阅，不视为所有新机的自动放行标准。

### 10.2 机械零位与方向是使能前条件

1. 操作员确认全体松力；逐个手动小幅活动关节，核对发生变化的 ID，避免只核对标签。
2. 使用明确的装配零位标记、夹具或图纸参考姿态，记录舵盘/输出轴与连杆的安装关系、Drive Mode、Homing Offset 和编码器读数，并拍照保存在本机。
3. 手动小幅屈伸，记录规定正方向下读数增减。左右镜像安装不直接推出偏置应一正一负，方向与零点分别判断。
4. 核对零位、机械限位及完整计划路径，不能仅以寄存器 0–4095 范围代替真实机构可达范围。装配不一致先修正装配或提出经过计算的校准方案；未经确认不写方向或偏置。
5. 校准记录和新偏置经用户确认、写后回读，再安排固定机器人后的单关节小幅验证。最后才考虑整腿或全体默认站姿。

当前 `plan-standing-pose.py` 只检查配置和数值范围，不知道机械装配是否正确。现有动作脚本没有自动证明机械路径安全的能力；新机不能跳过此节直接运行整腿站姿。

### 10.3 动作测试另行放行

仅在前两节通过、机器人已固定、操作员明确确认后，审阅具体 ID、目标、行程和停止方案。现有 `move-to-standing.py` 面向 14 台，`move-legs-to-standing.py` 仅面向十台腿部；默认只预览，运动要求 `--enable-and-stand --robot-fixed`，`--relax` 是独立松力操作。

本次限速方案为临时 Profile Acceleration=2、Velocity=10，约 13.74°/s，25 秒内连续三轮最大位置误差 ≤12 计数；成功后保持扭矩，异常请求松力并恢复 Profile。此方案属于本地试验，不是原版固定参数，不能在实际机构异常时通过放宽容差来判为通过。故障松力后必须另行读取 Torque Enable 确认结果。

本台曾在 ID30 使能回读失败，原因仍待确认；后来仅腿部使能成功但站姿超时，用户发现右膝弯折方向异常。新机记录必须分开填写通信、参数、机械校准和动作四个结论。完整运控仍有 15 关节及 ID200 假设，当前不直接启动原版 robotd。

## 11 收尾和验收签收

每台机器按模板逐项标记通过、失败、待测或不适用，附操作员、版本、证据路径和遗留问题。原始采样可按任务约定删除，但配置前后值、恢复结果、通过条件和失败原因应保留本机文字记录；没有原始数据时如实标明。

测试结束后确认临时采样/录音已退出、传感器配置已恢复、音频默认值正确。发生过舵机测试时独立核对实际扭矩状态，并由操作员安排支撑、关机和电源断开。**机载电脑关机不等于舵机或 HAT 外部电源已经断开。**

保存本台的部署清单和 SHA256，通用文件按版本共用、本机差异单独保存，不能用工作目录中某个文件的存在替代板端实际版本核验。未来软件变更按受影响项目复测，不把尚未完成的机械校准、全双工、IMU 融合或低压保护标为完成。
